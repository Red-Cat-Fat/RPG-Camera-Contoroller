# Логические блоки
- На сцене есть GameBootstrap, который спавнит игрока с камерой, инициализирует управлени и прочее.
- ActorSelectorService это скорее как прослойка к запросу активного персонажа, за которым нужно следить. Идея такая, что при смене фокуса на другого персонажа он будет выбираться через этот сервис, но так как в ТЗ персонаж был один - оставил для расширения.
- IInputService имеет только 1 реализацию, чисто для Etitor. Пока просто взял старую систему инпутов, через захордкоженные кнопки. Опирается на FrameUpdater для получения эвентов о смене кадра.
- Actor - это главный компонент персонажа. Идея в том, что это его "мозг", который в свою очередь отдаёт команды остальным компонентам.
- ActorMovement - механика перемещения. Просто использовал NavMeshAget'a без доработок.
- ActorAnimation - компонент визуализации. Его идея в том, чтобы слушать остальные компоненты и визуализировать логику. Так как просто 2 стейта идёт или стоит, то опираюсь только на bool (движится или нет вообе). Так как не было задачи реализовать плавное ускорение - не использовал float для скорости передвижения персонажа (если нужно - могу дать доступ к личному репозиторию, где такая механика настроена)
- MonoConstruct использовал для контроля жизненного цикла, так как нет ни фабрик, ни полноценного DI. 

# Камера
- Есть CameraRig, которая летает по сцене, следит за персонажем.
- Под рукой был BG3, потому механику взял за референс оттуда, просто ужал расстояние, на котором камера начинает замедляться, либо происходит телепортация к игроку, чтобы было нагляднее.
- WASD управление отвечает за перемещение по сцене. (см. который отвечает за перемещение от персонажа MoveCameraMechanic)
- Space для фокуса на игроке (отлипает после WASD)
- Зум на колёсике мышки (см. ZoomCameraMechanic)
- QE реализовывать было не обязательно, но я сделал просто потому что могу и это было быстро. (см. RotateCameraMechanic)
- При удалении на определённое расстояние начинаю замедлять скорость.
- Чтобы камера не замерла насовсем в мёртвой точке вычисляю скалярное произведение векторов направления камеры к игроку и направления движения, чтобы камера при движении от края к игроку набирала дополнительную скорость, дабы "выйти" из залипания.
- Для зума сделал компонент CatmullRail, который задаёт правила движения камеры (сделал так, чтобы не привязывать зумирование к одной точке обзора, да и показать, что умею рисовать разные редакторские штуки)
- Отталкивание от сцены сделал через NavMesh, чтобы не использовать физику, хотя в случае отсутствия NavMesh в определённом радису подстраховываюсь рейкастом вниз. Всё в компоненте HeightCameraMechanic.
